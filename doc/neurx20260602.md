## 2. Codex capabilities that are still worth bringing into NeurX

### 2.1 Thread resume, branching, and compact history

Codex has an explicit thread model with `startThread()` and `resumeThread()`.
NeurX has task-session restore, but not a first-class thread abstraction yet.

What to add:

- thread id as a first-class concept
- resume a previous thread without rebuilding from scratch
- branch a thread into a new task line
- compact or archive old turns while keeping the current turn active

Why it matters:

- makes long tasks easier to continue
- gives the user a clear "task lineage"
- reduces friction when a task spans many turns

### 2.2 More granular sandbox and approval policy

Codex exposes sandbox modes and approval policies such as:

- `read-only`
- `workspace-write`
- `danger-full-access`
- `never`
- `on-request`
- `on-failure`
- `untrusted`

NeurX currently has a simpler approval model.

What to add:

- per-task sandbox mode
- per-command approval policy
- read-only browsing mode
- stricter handling for destructive commands
- optional network allow/deny policy

Why it matters:

- better safety for high-risk edits and commands
- closer to the Codex user experience
- fewer prompts when a task is clearly safe

### 2.3 Structured execution timeline

Codex models runs as explicit items such as:

- command execution
- file change
- MCP tool call
- web search
- todo list
- reasoning
- agent message
- error

NeurX has chat and tool cards, but not a fully unified execution timeline.

What to add:

- a turn timeline view
- separate event types for command, patch, search, MCP, and web fetch
- item-level status tracking
- replayable turn history

Why it matters:

- easier debugging
- better trust and review
- more obvious what the agent actually did

### 2.4 Skills and slash commands

Codex uses skills and command-like shortcuts as part of the workflow.
NeurX has strong prompts and tool support, but not a full skills surface.

What to add:

- workspace-local skill loading
- `/plan`, `/review`, `/checkpoint`, `/search`, `/delegate`
- `AGENTS.md` or similar instruction discovery
- command templates for repeated workflows

Why it matters:

- reduces repeated prompting
- gives the app a more "agent-native" workflow
- makes behavior more discoverable

### 2.5 Image input and structured output

Codex supports local image input and structured output schemas.

What to add:

- attach screenshot or image as agent input
- use structured output for review / plan / checklist tasks
- support schema-driven responses for specific workflows

Why it matters:

- useful for UI bugs, screenshots, and design review
- reduces ambiguity in agent replies

### 2.6 Better task-level Web controls

Codex has task parameters for:

- web search mode
- web search enablement
- network access
- additional directories

NeurX already has web search tools, but not a task-parameter layer.

What to add:

- task-scoped network toggle
- explicit web search mode
- extra workspace roots or attachable directories
- read-only external browsing mode

Why it matters:

- makes tasks safer and more reproducible
- avoids over-broad access by default

### 2.7 File-change review as a first-class object

Codex surfaces patch and file changes as separate items.
NeurX already has patch and checkpoint support, but the review surface can be stronger.

What to add:

- diff summary cards
- per-file change list
- accept / reject at hunk or file level
- restore from a named checkpoint with preview

Why it matters:

- clearer edit review
- better rollback confidence
- easier to understand large changes

### 2.8 Headless and SDK-style entry points

Codex has CLI and SDK entry points, plus non-interactive usage.
NeurX is still mainly a desktop app.

What to add:

- command-line task submission
- headless run mode for batch work
- programmatic session start / resume
- remote or local automation hooks

Why it matters:

- enables scripted workflows
- makes NeurX useful outside the GUI
- opens the door for CI-like or batch repair use cases

## 3. What NeurX should not rush to copy wholesale

These can be useful later, but they would change the product shape too much if
we copied them directly:

- full cloud or remote orchestration platform behavior
- multi-channel inbox / messaging assistant behavior
- heavy voice-first companion workflows
- broad workflow-canvas style platform features

Those are valid ideas, but they are not the shortest path to a better coding
agent.

## 4. Recommended priority order

### Phase 1: highest leverage

1. Thread resume and branching
2. Granular sandbox and approval policy
3. Structured execution timeline
4. Stronger file-change review and rollback UX

### Phase 2: high leverage

1. Skills and slash commands
2. Image input and structured output
3. Task-level web and network controls
4. Headless and SDK-style entry points

### Phase 3: expansion

1. More advanced workflow visualization
2. Voice or desktop-companion features
3. Remote control or multi-channel surfaces

## 5. Practical NeurX direction

If we want NeurX to feel closer to Codex without losing its desktop identity,
the best path is:

- keep the workspace/editor/chat layout as the core
- make task state, plan state, and history first-class
- make approval and rollback more granular
- add a structured event stream for debugging and review
- add skills and command shortcuts for repeatable workflows

That gives us the most Codex-like value without turning NeurX into a different
product.

## 7. Suggested order of attack

If we want the fastest visible improvement, do these in order:

1. Thread resume and branch metadata
2. Granular sandbox and approval policy
3. Structured execution timeline
4. Skills and slash commands
5. Image input and structured output
6. Headless entry point

That sequence gives us the biggest gain in trust, persistence, and usability
before expanding into more advanced surfaces.
