# Native tensor construction and memory

Ordinary native `array_set` allocates a fresh length-prefixed array and copies all cells before changing one cell. This implements value semantics for aliases and function arguments. Repeating it for N cells costs O(N²) copied bytes. This instruction and its MIR/native representation remain unchanged.

The selected alternative is a typed opaque TensorBuilder with bulk operations. COW needs proven uniqueness across every alias, and views require representation/ABI changes; neither is required for safe linear construction. A monotonically increasing positive integer identifies a GC-managed descriptor, never a raw user pointer. Float, integer and string builders have distinct kinds. The descriptor is linked into a registry whose actual head slot is inside the native GC root interval before backing allocation. The collector can therefore reach unfinished arrays and their string elements during allocation pressure.

`new_*_builder` allocates zeroed storage once. Typed indexed/fill/copy operations change only that unpublished storage. Wrong IDs, kinds, bounds and sealed buffers return negative error codes. A checked typed seal followed immediately by take publishes the existing array without copying, consumes the handle, and invalidates every copied handle. Double finalization and later mutation fail. Explicit release unlinks the descriptor for collection; storage is not manually freed. The current native runtime is single threaded.

The file interface returns a positive float-builder handle or a negative error. Zero-length successful reads return a valid handle, distinct from EOF (`-61`), missing files (`-2`), invalid arguments (`-22`), overflow (`-75`) and OS I/O errors. Partial reads accumulate complete elements; an incomplete requested range fails and releases the unpublished buffer. BF16/F16/F32 conversions preserve IEEE signed zero, subnormals, infinity and NaN. Public S wrappers return `{ok, values, error}` and guard seal/take.

Pure bulk slices and patches allocate one result and preserve the source. Constructor counters measure logical allocation calls, requested bytes, allocator-rounded bytes, copied bytes, indexed stores, live descriptors, bytes read and decoded elements. They do not count every process allocation. Native GC allocation rounds to powers of two, explaining the 128MiB backing allocation for 10 million f64 cells. Runtime OOM remains governed by the existing allocator; C fault-injection tests separately verify descriptor cleanup if an allocator returns null.

Evidence: `artifact/local-inference/array-construction-20261110/`. Indexed construction has six size measurements in `bench/precise-indexed-results.json`; BF16 bulk loading has six in `bench/bf16-bulk/results.json`. Benchmarks record compiler hash, wall/CPU time, per-child peak RSS and construction counters. `test/native-construction/benchmark.py` reproduces BF16 measurements into a new output directory. ASan/UBSan are enabled; LeakSanitizer cannot enumerate sandboxed threads and is explicitly disabled. Native GC-pressure regressions cover both programs with and without S globals, string reachability, copied handles and finalized array aliases.

Compiler modifications are preserved as the incremental patch `tool/toolchain-patches/20261110-native-builders.patch`, applied after the earlier byte-index repair. No bootstrap artifact is renamed to represent a later stage.
