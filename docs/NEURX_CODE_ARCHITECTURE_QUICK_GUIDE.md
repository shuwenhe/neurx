# NeurX Code 架构设计 - 快速参考

## 一句话总结

NeurX Code 采用 **"AI 决策 + 标准验证 + 快速执行"** 的分层架构，实现了很强的功能、跨平台支持和灵活性。

## 核心三层架构

### 第 1 层：AI 决策 (模型适配层)

```
任务: "Create a user authentication system"
    ↓
模型理解并规划
    ├─ 项目结构
    ├─ 安全考虑
    ├─ 最佳实践
    └─ 具体步骤
    ↓
输出: 标准化的工具调用 (JSON)
{
  "tool_name": "Write",
  "input": {"file_path": "auth.py", "content": "..."}
}
```

**为什么需要 AI 决策？**
- 理解自然语言意图
- 推理最佳方案
- 考虑上下文和约束
- 学习和改进

### 第 2 层：安全验证 (Hook System)

```
工具调用 (JSON)
    ↓
Hook 验证脚本
    ├─ 路径遍历检查
    ├─ 权限检查
    ├─ 敏感信息检查
    └─ 自定义规则
    ↓
决策: Allow / Deny / Ask User
```

**为什么需要 Hook？**
- AI 不是完全可靠
- 用户有不同的安全需求
- 企业需要审批流程
- 无需改源代码即可定制

**示例 Hook**：
```bash
# ~/.neurx/hooks/validate.sh
if [[ "$file_path" == /etc/* ]]; then
  exit 2  # Deny
fi
```

### 第 3 层：快速执行 (Node.js)

```
执行工具调用
    ├─ fs.writeFileSync() ← Write
    ├─ execSync()         ← Bash
    ├─ 字符串替换          ← Edit
    └─ 其他操作
    ↓
返回结果
```

**为什么用 Node.js？**

| 原因 | 说明 |
|------|------|
| **跨平台** | npm install 即可，无需编译 |
| **快速开发** | 简单语法，包管理完善 |
| **异步 I/O** | 高效处理文件操作 |
| **无依赖** | 只需 Node.js 18+ |

## 为什么不选择其他方案？

### ❌ 完全本地模型 (Ollama/LLaMA)

```
用户 → 本地 LLaMA → 工具执行
```

**问题**：
- 需要额外接入模型适配层
- 需要 GPU（昂贵 + 复杂配置）
- 每个用户下载 GB 级模型
- 维护困难

### ❌ C++ 实现

```
用户 → 模型适配层 → C++ 工具执行
```

**问题**：
- 编译慢，部署复杂
- 跨平台困难
- 开发速度慢
- 学习曲线陡峭

### ✅ Node.js 实现 (外部参考实现)

```
用户 → 模型适配层 → Node.js 工具执行
```

**优点**：
- ✅ 清晰的工具执行链路
- ✅ 跨平台（npm install）
- ✅ 快速部署和开发
- ✅ 灵活的 Hook 系统
- ✅ 丰富的 npm 生态

## Tool Use 标准接口

```
为什么使用 Tool Use？
```

**原因 1: 可靠性**
```
方案 A - 自然语言
Agent: "I'll create app.py with..."
App: 需要解析自然语言 ❌ 容易出错

方案 B - Tool Use (JSON)
{
  "tool_name": "Write",
  "input": {"file_path": "app.py", "content": "..."}
}
App: 直接执行 ✅ 可靠、可验证
```

**原因 2: 标准化**
```
各种主流模型提供方都支持 Tool Use
任何 LLM 都能用同样的工具
未来可以轻松切换模型提供方
```

**原因 3: 安全性**
```
Tool Use 生成的是结构化 JSON
可以在执行前进行验证
比自由格式的自然语言更容易检查
```

## Hook 系统的妙处

### 为什么不硬编码验证规则？

```
❌ 硬编码版本
if (path.startsWith('/etc')) deny();  // 在源代码里
问题: 用户无法定制

✅ Hook 版本
# ~/.neurx/hooks/validate.sh
if [[ $path == /etc/* ]]; then exit 2; fi
优点: 用户可以改，无需改源代码
```

### Hook 的强大之处

```
基础功能: 验证文件操作
          ↓
扩展应用:
├─ 企业审批流程
├─ 合规性检查
├─ 审计日志
├─ 用户通知
└─ 自定义规则
```

**企业场景**：
```
Startup A 的规则: 禁止 /etc
Startup B 的规则: 禁止 database/ 的修改 + 需要审批
企业 C 的规则: 需要同意隐私协议

所有都用同一个执行框架，但规则完全不同
这就是 Hook 系统的妙处！
```

## 设计哲学

```
外部参考实现的设计哲学:

1. 职责分离
   模型做决策 (适配层)
   脚本做验证 (Hook System)
   Node.js 做执行 (工具)

2. 最小化依赖
   只需 Node.js 18+
   无需特殊库或驱动

3. 最大化灵活性
   用户通过 Hook 自定义规则
   无需修改源代码

4. 开放的生态
   标准的 Tool Use 接口
   社区可以扩展
   其他应用可以复用
```

## 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| AI 来源 | 模型适配层 | 可替换、可验证 |
| 接口标准 | Tool Use (JSON) | 可靠、可验证、标准化 |
| 验证方式 | Hook System | 灵活、用户控制 |
| 执行环境 | Node.js | 跨平台、快速、简单 |
| 分发方式 | npm | 零配置、自动更新 |
| 用户界面 | CLI | 开发者友好、快速 |
