启动和管理:
  一键启动          bash deploy.sh
  启动 API          docker compose --profile api up -d neurx-api
  启动 GPU 模式     docker compose --profile gpu up -d neurx-gpu
  下载模型          docker compose --profile download up download-model
  停止服务          docker compose down
  重启服务          bash restart.sh
  停止服务          bash stop.sh

验证和测试:
  健康检查          curl http://localhost:8000/health

⚙️  配置调整
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

编辑 docker-compose.yml 中的环境变量:

  NEURX_INFER_DEVICE: cpu              # CPU 或 GPU 推理
  NEURX_S_PORT: 8000                   # 服务端口
  NEURX_CPU_THREADS: 8                 # CPU 线程数 (根据核心数调整)
  NEURX_CHAT_MAX_NEW_TOKENS: 2048      # 最大生成 token 数

修改后重启服务:
  docker compose restart neurx-api

🐛 故障排查
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

问题 1: 脚本无执行权限
  解决: chmod +x deploy.sh test.sh restart.sh stop.sh

问题 2: Docker 找不到
  解决: curl -fsSL https://get.docker.com | sh

问题 3: 端口被占用
  解决: lsof -i :8000 && kill -9 <PID>
        或运行脚本会自动清理

问题 4: 模型文件不存在
  解决: 脚本会提示下载，或手动:
        docker compose --profile download up download-model

问题 5: 服务无法启动
  解决: docker logs neurx-api-server -f
        查看详细日志诊断

问题 6: 公网无法访问
  解决: 检查防火墙/云平台安全组是否允许 8000 端口
